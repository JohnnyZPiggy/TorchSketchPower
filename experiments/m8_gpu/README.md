# M8 paired accuracy/time/allocator pilot

Issue #20. This is a preregistered bounded pilot, not a speedup claim. Production code, M4/M5/M7 evidence and SAE pin stay unchanged.

Grid: (256,128), (1024,512) x geometric/polynomial/near-flat x float32/float64 = 12 matrices; (2048,1024) x geometric x both dtypes = 2. CPU timing only for the smallest geometric dtype pair. CUDA gets 70 method configurations; CPU gets 10. SPI steps 0/1; torch.svd_lowrank q=s=16, niter 0/1; separate dense SVD baseline. r=8, ell=d=32. steps/niter are distinct axes, not equivalent arithmetic. Each algorithm returns rank-r U,S,Vh (svd_lowrank V is conjugate-transposed). One independent matrix/sketch seed, 1 first measured call, 1 warmup and 3 warm repeats; alternate forward/reverse method order. Repeat RNG seeds are replayed, not independent accuracy samples.

Accuracy tiers are fixed before data: Frobenius error / Eckart-Young optimum <=1.10 and <=1.50. Every timed configuration gets residual singular values and an independent Frobenius-vs-SVD-sum audit, reference singular values, exact paired input synthesis seed/hash and normalized Frobenius/spectral errors. Pareto and eligible matched-quality sets can be empty. Near-flat results are interpreted alongside M5 stage diagnostics, without inferring mechanism from timings.

Timing excludes synthesis/transfers/accuracy (separately disclosed), includes RNG/sketches/rank scalar sync/solve/SVD. Wall is synchronized; CUDA events cover the same whole default-stream call INCLUDING idle intervals, not kernel-only. First-call is per config after gate/reference work, not fresh-process cold. All raw warmup/cold/warm trials, warnings and full exceptions are retained. Allocator current/reserved baselines and absolute/delta peaks are not true per-call or device-wide allocation. No empty_cache. CPU allocator/event metrics are NOT MEASURED. Thermal/clocks sampled via nvidia-smi if available. Single T4/session and three repeats do not establish replicated benchmark conclusions.

Use existing pinned .sae/tools/compute/colab_control.py with committed driver/manifest and exact source SHA. The driver reuses M7's non-editable installation/provenance helper, runs short installed-package M7 correctness BEFORE timings, then runs M8. Outer artifact PASS means a report was transported; inspect benchmark_status and coverage. Gate failure prevents benchmarks. The runtime uses an overall <=900s task, <=300s allocation lifecycle, >=60s cleanup reserve; the 170s runner is additionally capped by controller remaining time. No retries or grid expansion. A last-completed-matrix checkpoint preserves earlier outcomes on external timeout. No data truncation to fit <=1MiB: oversized reports are transport failures, not fabricated success.

CPU smoke: python experiments/m8_gpu/run_m8.py --device cpu --smoke --source-sha EXACT_SHA --out NEW_DIRECTORY

Offline CPU smoke is DRY_RUN_CPU, never GPU evidence. Full remote artifact includes losslessly zlib/base64-compressed raw benchmark JSON (no rounding or row removal), raw CSV/summary/manifest strings, complete gate results, install identity and full command stdout/stderr. Decode the exact raw JSON bytes using the encoding specified in the artifact and check against its SHA256; publish decoded files for review. Compression keeps full residual singular values within the existing 1MiB transport limit. No new dependencies, compile, TPU, custom kernels, Panther/skerch, sparse-sign or one-pass claims.

API sources: https://docs.pytorch.org/docs/stable/generated/torch.svd_lowrank.html (dense randomized SVD may be slower than dense exact SVD); https://docs.pytorch.org/docs/stable/notes/cuda.html (synchronization and allocator semantics). Runtime records actual torch version; APIs are independently tested on the installed runtime.
