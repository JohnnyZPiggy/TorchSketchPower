# M9 compile feasibility audit (Issue #22)

Probe only: compiling a graph is not an acceleration result. Production src and the pinned SAE runtime are unchanged. Prior M7 correctness and M8 partial/negative observations remain archived; no M8 failures are reclassified here.

Inventory: core numerical-rank `int(tensor.sum())`, norm-to-float, rank branching/exception; reconstruction Gram/SVD scalar reads, conditioning warnings and CPU gelsd/CUDA gels solve; public device/generator/shape validation and random sketches all remain active. Static steps does not make these data-dependent safety checks capturable. The experiment never uses on_rank_deficient=ignore, removes a rank check, patches compiler behavior or enables suppress_errors.

CPU plan: one 32x24 Gaussian matrix per float32/float64, r3/s6/ell8/d10, steps0/1. Eleven bounded cases: fixed-sketch three-matmul helper with Inductor and aot_eager (both dtypes), public API with aot_eager fullgraph=False (steps0/1, both dtypes), public Inductor exploratory float64, public aot_eager fullgraph=True expected-failure diagnostic, and a float64 corange ill-conditioned/rank-deficient control. The helper compiles exactly Y=A Omega, Z=A Phi, W=Psi A; composition still runs the original checked subspace/reconstruction functions. It is not a compiled full pipeline. Each child process has a finite timeout and a private Inductor cache. Backend execution failure prevents later retries of that backend. Batch deadline marks untouched cases NOT_RUN.

Control A seed123; sequential Gaussian Omega/Phi/Psi seed314 reproduce the public RNG stream. Pure helpers use pre-generated sketches, excluded from timing; public calls include the real draws and checks, resetting a same-device generator in the measured-call wrapper. Compare reconstructed matrices/residuals and singular values, not vector signs/phases. Well-conditioned paired comparison uses existing CPU oracle tolerances 1e-3 float32 /1e-9 float64; corrupted/nonfinite results fail. Rank-zero A must raise the same RankDeficiencyError; forced condition-limit warnings must remain. A separate actual ill-conditioned C=diag(1,1e-10) must warn and solve accurately; singular C must raise.

Record wrapper creation and first compile+run separately from three warmed calls (one warmup per mode). Whole-call synchronized CUDA wall and event intervals are distinct; event includes stream idle, not kernel-only. CPU event/allocator metrics NOT MEASURED. CUDA allocator baseline/peak/delta are not device-wide/per-call true allocation. Explain runs AFTER measured calls, and records graph counts/reasons/raw text when available. Explain uses its documented diagnostic API, not the selected optimizing backend; graph segmentation is not a measured kernel count. aot_eager is a debugging/AOT tracing backend without optimized codegen and cannot substantiate acceleration. First calls use fresh processes/cache paths but are not machine/library cold.

Classes: SUPPORTED means the scoped callable executed and paired checks passed; GRAPH_BREAK means successful partial execution with observed break(s), not fullgraph support; UNSUPPORTED retains complete exception/timeout/logs; CORRECTNESS_FAIL stops that worker's timings; NOT_RUN means no execution. Failed fullgraph capture is an expected negative result, never patched into success. CPU explanation/version behavior does not predict CUDA backend support.

Optional T4 gate: only if a CPU Inductor helper is SUPPORTED and no CPU correctness mismatch, use one existing-controller session, exact noneditable SHA installation, fresh strict authenticated-zero/entitlement and short installed-package M7 CUDA gate. GPU plan is the same eleven cases on 256x128, r3/s6/ell8/d10 (smaller fixed grid than Issue examples), <=160s batch, <=40s worker, <=900s task, <=300s allocation lifecycle, >=60s cleanup reserve. Deadlines may leave partial data. No auto retry or second session. Reuse the M7 install helper and M8 driver/artifact transport pattern; no controller/adapter extension. Download compressed exact JSON and CSV/summary hashes; stop and strictly verify zero. No headline speedup or break-even claim is produced by this pilot; compile overhead and diagnostic-backend times are disclosed.

Reproduce CPU in a clean exact-source clone with a noneditable installed package:

    python -I experiments/m9_compile/run_m9.py --source-sha EXACT_SHA --device cpu --out NEW_DIRECTORY --max-seconds 360

Offline driver uses M9_DRIVER_DRY_RUN=1 and the same CPU plan; it is not GPU evidence. Main command refuses dirty/mismatched source. No production changes, new dependencies, custom kernels, backend configuration hacks, Actions, new billing, TPU or merge.

Sources: [PyTorch compile FAQ](https://docs.pytorch.org/docs/stable/user_guide/torch_compiler/torch.compiler_faq.html), [official troubleshooting source](https://github.com/pytorch/pytorch/blob/main/docs/source/user_guide/torch_compiler/torch.compiler_troubleshooting.md). Actual API behavior/torch version are recorded rather than assumed from current documentation.
